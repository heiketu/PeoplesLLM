# MAX-EFFORT：空闲内存换均衡——EP 层的感知式额外镜像设计

> **状态标注（H0, 2026-08-23）：implemented**（P0 拓扑工具链、P3 路线 A `GGML_REMOTE_EP_MIRROR=1` 已双机实测，注意小档 PP ≤256 token 回归需关闭）；**experimental**（其余路线未落地）。

状态：P0 工具已落地（ep-topo-probe / ep-topo-run.sh / ep-plan.py / ep-topo-profile.json）；
**P3 路线 A（层内专家级静态比例拆分）已实现并双机实测**（2026-07-30，commit 115622070，
`GGML_REMOTE_EP_MIRROR=1`，见 README "层镜像 + 专家 slot 拆分" 节）

## 1. 动机

正常 EP 配置下，CPU 节点的内存大量空闲，且内存容量与带宽能力并不对应：

- DSV4（Q3_K 89G）当前最优配置（slave 35-42 共 8 层）：master RSS 45.8G / 总 256G，
  slave RSS 10.2G / 总 128G——**两端各有 >100G 内存闲置**。
- 拓扑探测（tools/epd/ep-topo-profile.json）显示系统存在结构性不均衡：
  - slave node1 因 2DPC 内存慢 ~14%（93.8 vs 80.2 GB/s），同机两节点不同速；
  - 跨 socket 缓存线转移 ~600ns（同 socket ~250ns）；
  - 跨机 TCP 64B RTT ~40-70us、p90 偶发 >130us；实测 726 token 中 452 次 RPC 尖峰 >2ms。
- 均衡约束（ep-plan.py）：`Ls·(t_slave+t_net) = Lm·t_master`，当前最优 Ls=8 是
  min-max 关键点；任何一侧的瞬时抖动（OS、页入、网络）都直接拉长关键路径，
  因为远端 RPC 是阻塞式的，尖峰无法被另一侧吸收。

**核心思想**：空闲内存是免费的冗余。用拓扑感知数据指导**额外镜像部分层的权重**，
把冗余内存换成 (a) 运行时负载均衡（分担）和 (b) 尾延迟/同步开销的下降（热备对冲）。

## 2. 观测与决策基础

镜像选择不是拍脑袋，输入全部来自已落地的 P0 工具：

- `ep-topo-profile.json`：六节点两两延迟矩阵（缓存线 ping-pong / TCP ping）、
  激活级载荷（8K/32K/128K/512K）往返、各节点 membw 本地带宽（median + p90）。
- `ep-plan.py`：关键路径模型 `T = max(Tm,Ts) + (1-β)·min(Tm,Ts) + C`，
  β=0.789、C=30.57ms 由三组实测锚点校准（误差 ≤1.5%）。

**镜像候选集**（按当前系统实测不均衡排序）：

| 候选 | 修正的不均衡 | 内存代价 | 预期收益 |
| --- | --- | --- | --- |
| M1: slave node1 承担的层在 node0 加镜像 | 2DPC 慢 14% | snode0 +~2G/层 | 消除 slave 内部短板，Ts 方差↓ |
| M2: slave 远端尾部 2-4 层在 master 加镜像 | RPC 尖峰（452/726 >2ms） | master +4-8G | p90/p99 尾延迟↓，屏障抖动↓ |
| M3: 远端边界层（35 附近）双端共有 | 主/从切换与拆分调度 | 两端各 +2G/层 | 为 P3 专家级拆分提供载体 |
| M4: GPU 卸载层在 CPU 侧加镜像 | GPU 段 26ms 占 66%，抖动无兜底 | CPU +~2G/层 | 仅热备，收益有限，优先级最低 |

**选择算法（贪心）**：对每个候选镜像 m，用规划器模型 + profile 的 p90 估计
边际收益 `Δ(m) = (T_before - T_after) / mem_cost(m)`，在内存预算约束下按 Δ 降序选取。
约束：每节点镜像后 RSS 上限 = 节点内存 × 0.7（留页缓存与 OS）。

## 3. 热备还是分担？

两种语义都要，但**分阶段、按路径分别选择**。

### 3.1 热备（hedged standby）——先做这个

- 机制：主路径请求发出后，若超过阈值（取 profile 的 p90，如 RPC 200us 未回）
  就向镜像副本发对冲请求，**取先到者，丢弃后到者**。
- 为什么安全：MoE 专家 FFN 是纯函数 `y = down(silu(gate(x))·up(x))`，幂等；
  同一权重、同一 x86 指令路径下两副本输出 bit 级一致，取先到者**不引入数值不确定性**
  （GPU↔CPU 跨架构镜像不满足此条件，故 M4 只能用于可用性兜底而非对冲）。
- 收益：不改稳态吞吐，专门削尖峰——直接针对实测的 452/726 RPC >2ms 与
  barrier 2.6-4.7ms 抖动。同步开销为零（无新屏障）。

### 3.2 分担（sharing）——稳态吞吐的下一步

分担要改变均衡点，需要运行时调度语义。两条路线对比：

**A. 层内专家级静态比例拆分（推荐）—— ✅ 已实现（2026-07-30，commit 115622070）**

- 落地形态：`GGML_REMOTE_EP_MIRROR=1`（+`_MIRROR_LAYERS`/`_MIRROR_KREMOTE`）。
  master 镜像远程层权重，每层 top-k 按 slot 维静态拆 [0,k_r) 远程 / [k_r,k) 本地，
  默认 k_r=n_expert_used/2（clamp [1,k-1]），离线可调，运行时无调度器——与本节
  原设计一致。同步语义用两个 custom op 夹住本地子图（send 只发不等 / wait 收
  partial_r），合并顺序固定（partial_r 先、本地 slot 升序），与全远程基线结合
  顺序一致，GLM+DSV4 gen48 逐字 IDENTICAL，worker 零改动。
- 实测（同会话 ABBA 反序，详见 README 实测节）：TG GLM +10.6% / DSV4 +9.3%；
  大档 PP GLM(1020) +27.4% / DSV4(985) +10.9%；每层 decode wait -80~84%。
  小档 PP 回归（GLM 63 -18.6%、DSV4 245 -5.6%），根因是 master 本地 CPU MoE
  小批次固定权重读取带宽短板（README 63-token 档已有记载），非拆分本身。
- 原设计细节（保留备查）：DSV4 每层 top-6 专家互相独立，输出是 router 权重加权和
  `y = Σ_{i∈top6} w_i·expert_i(x)`。天然可把 6 个专家拆成两组（如 4+2、3+3），
  并发送主副本与镜像副本，**两组结果到齐后按固定顺序加权合并**。
- 拆分比例来自 profile 带宽比（如 snode0:snode1 = 93.8:80.2 → 4:2 取整），
  离线由 ep-plan.py 计算并固化在启动配置里——**运行时不需要调度器**，无抢占、无队列。
- 同步语义：
  - 层边界本来就是图执行的天然屏障，拆分只发生在层内，**不改图语义**；
  - 浮点非结合性：合并顺序固定（主组先、镜像组后）→ 结果确定性、可复现，
    与基线的逐 token 一致性验证（temp 0 / seed 42）照常适用；
  - 现有 ep-transport 的 REQ/RESP 合并语义直接推广为"两组 RESP 合并"。
- 收益：等效于把慢节点的欠载转移给快节点/空闲端，均衡点 N* 右移，
  或在同一 N* 下缩短 Ts 的 max 项。规划器估计：slave 有效带宽 +10~15%
  时 N* 从 8 移到 9-10，TG 预期 +2~4%（需实测验证）。

**B. work-stealing（仅限同机跨 socket，不推荐跨机）**

- 共享内存的专家粒度任务队列，快节点偷慢节点任务。同机跨 socket 缓存线
  转移 ~600ns，队列操作开销可被专家计算（~0.1ms/专家）摊销；跨机 RTT ~40us
  起步，每层每 token 只有 6 个专家任务，任务太碎，调度开销吃掉全部收益。
- 结论：跨机一律静态比例；work-stealing 仅作为 P4 同机优化探索。

## 4. 分阶段实现路径

| 阶段 | 内容 | 依赖 | 验证标准 |
| --- | --- | --- | --- |
| P0 ✅ | 拓扑探测 + profile + 规划器 + 校准（本目录已交付） | — | 锚点误差 ≤1.5%，复现 Ls=8 |
| P1 | slave 双 worker 按节点非均衡拆分（snode0:snode1 按 93.8:80.2），`GGML_REMOTE_EP_LAYERS` 扩展为多段范围 + 多端点 | 现有 llama-epd，传输层支持 2 端点 | TG512 ≥ 单 worker 8 层配置；snode1 不再是短板 |
| P2 | 热备对冲（M2）：master 镜像 slave 尾部 2-4 层，传输层加 p90 超时对冲请求 | P1；master 空闲 >100G | RPC >2ms 尖峰比例从 62% 降到 <10%；TG512 不降 |
| P3 ✅ | 专家级静态拆分（路线 A 已落地：`GGML_REMOTE_EP_MIRROR=1`，层镜像 + slot 维静态比例拆分，固定顺序合并；M1/M3 的双端共有载体以"master 镜像远程层"形态实现） | 现有图挂点（双 custom op 夹本地子图） | 逐字 IDENTICAL ✅；TG +9~11%、大档 PP +11~27% ✅；N* 右移未测（拆分在层内，不改层数分配） |
| P4 | 同机跨 socket work-stealing 探索 + 规划器闭环（profile→plan→部署→实测回写校准） | P3 | TG 与 p90 双指标回归报告 |

每阶段完成后更新 ep-plan.py 的校准锚点（新增实测点进 ANCHORS），保持模型误差 <3%。

## 5. 明确不做

- 跨机 work-stealing / 分布式任务队列（第 3.2-B 节已论证负收益）。
- GPU↔CPU 跨架构对冲（数值不 bit 一致，破坏可复现性验证）。
- 修改单机基线路径：所有镜像能力都是增量开关，默认关闭，回退行为 = 现状。
